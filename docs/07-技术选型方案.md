### 1.2 架构设计原则

| 原则 | 说明 |
|------|------|
| 前后端分离 | 前端和后端独立开发、独立部署，通过API通信 |
| 微服务化 | 按业务领域划分服务，降低耦合度 |
| 异步处理 | 耗时操作（AI生成）使用任务队列异步处理 |
| 缓存优先 | 热点数据使用Redis缓存，减少数据库压力 |
| 安全第一 | 数据加密、接口鉴权、内容审核 |

## 4. 数据库选型

### 4.1 关系型数据库：MySQL 8.0

**选型理由**：
- 成熟稳定、社区活跃
- 支持事务、外键约束
- 查询性能优秀
- 云服务支持完善（阿里云RDS、腾讯云MySQL）

**配置建议**：
```yaml
# 推荐配置
版本: MySQL 8.0
字符集: utf8mb4
排序规则: utf8mb4_unicode_ci
存储引擎: InnoDB
```

**核心表清单**：
| 表名 | 说明 | 预估数据量 |
|------|------|-----------|
| users | 用户表 | 10万+ |
| user_permissions | 用户权限表 | 20万+ |
| scripts | 脚本表 | 50万+ |
| works | 作品表 | 100万+ |
| tasks | 任务表 | 200万+ |
| orders | 订单表 | 50万+ |
| messages | 消息表 | 100万+ |

### 4.2 缓存数据库：Redis 7.x

**选型理由**：
- 高性能内存数据库
- 支持多种数据结构
- 支持持久化
- 作为Celery消息代理

**使用场景**：
| 场景 | 数据结构 | 过期时间 |
|------|---------|---------|
| 用户会话 | String | 7天 |
| JWT黑名单 | Set | Token有效期 |
| 验证码 | String | 5分钟 |
| 接口限流 | String + Lua | 1分钟 |
| 热点数据缓存 | Hash | 1小时 |

### 4.3 文档数据库：MongoDB 7.x

**选型理由**：
- 灵活的文档模型
- 适合存储非结构化日志
- 查询性能优秀
- 支持分片扩展

**使用场景**：
| 集合名 | 说明 | 保留策略 |
|--------|------|---------|
| operation_logs | 操作日志 | 180天 |
| ai_generation_logs | AI生成日志 | 90天 |
| error_logs | 错误日志 | 30天 |
| access_logs | 访问日志 | 30天 |

    command: celery -A app.tasks worker -l info
    depends_on:
      - redis
      - mysql

volumes:
  mysql_data:
  redis_data:

### 7.4 CI/CD流程

```yaml
# .github/workflows/deploy.yml 示例
name: Deploy

on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Run tests
        run: |
          pip install -r requirements.txt
          pytest

  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - name: Build Docker image
        run: docker build -t ai-platform:${{ github.sha }} .

  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to server
        run: |
          ssh user@server 'docker pull ai-platform:${{ github.sha }}'
          ssh user@server 'docker-compose up -d'
```

### 8.3 Git提交规范

```
<type>(<scope>): <subject>

type类型：
- feat: 新功能
- fix: 修复bug
- docs: 文档更新
- style: 代码格式
- refactor: 重构
- test: 测试相关
- chore: 构建/工具

示例：
feat(user): 添加用户注册功能
fix(payment): 修复支付回调验签问题
docs(api): 更新API文档
```
